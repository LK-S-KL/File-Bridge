# Rove 发布流程

这份清单适用于当前 CEP 版本。不要直接在日常开发分支上发布。

## 1. 准备候选版本

1. 确认待发布功能都已合并到 `main`。
2. 创建 `release/vX.Y.Z` 分支。
3. 运行 `npm run version:set -- X.Y.Z`，不要手工分别修改多个版本号。
4. 把 `CHANGELOG.md` 的 `Unreleased` 内容整理到对应版本，并写发布日期。
5. 运行 `npm test`，确认结果全部通过。

版本号规则：修复问题增加最后一位；新增兼容功能增加中间一位；不兼容改版增加第一位。测试版可以使用 `X.Y.Z-beta.N`，但 Adobe CEP manifest 的正式包建议保留三段数字版本。

## 2. Adobe 实机验收

- 在声明支持的最低 Premiere Pro 版本验证安装、打开面板、浏览素材、搜索、预览、导入和放到播放头。
- 在当前最新版 Premiere Pro 再验证一次。
- 涉及 AE 的变化必须验证导入和加入当前合成。
- 验证 NAS 离线、目录无权限、中文路径、空目录和大目录。
- 用干净的测试工程验证升级，不要只验证全新安装。

## 3. 打包与发布

1. 使用正式证书和既定 CEP 打包工具生成 `.zxp`；证书不得放进仓库。
2. 在另一台电脑或干净用户环境安装该包并做一次冒烟测试。
3. 合并发布分支到 `main`。
4. 创建带注释的 Git 标签：`vX.Y.Z`。
5. 在 GitHub Releases 创建草稿，附上安装包、更新说明、兼容版本和已知问题。
6. 下载 Release 中的安装包再验一次，确认后才正式发布。

已发布的安装包和标签不得覆盖。发现问题时发布新的修订版本，例如从 `0.2.0` 升到 `0.2.1`。
