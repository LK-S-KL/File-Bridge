## 5. P0 详细问题

### STAB-001：AE smoke 可能丢失未保存工程

- **位置**：`tests/ae-smoke.jsx:30-33`
- **类别**：数据安全 / 测试基础设施
- **证据**：脚本直接执行 `app.project.close(CloseOptions.DO_NOT_SAVE_CHANGES)`，随后调用 `app.quit()`；运行前没有创建隔离项目，也没有检查当前项目是否存在未保存修改。
- **影响**：开发者或测试人员手动运行脚本时，可能无提示丢失当前 AE 工程修改。
- **当前缓解**：该文件不在安装包中，也未纳入 `npm test`，但仓库内仍可被误运行。
- **修复方向**：测试启动时创建独立临时工程；记录原工程状态；禁止对未知工程使用 `DO_NOT_SAVE_CHANGES`；默认不退出 AE。
- **验收标准**：
  - [ ] 有未保存 AE 工程时脚本拒绝执行或要求人工确认。
  - [ ] smoke 只关闭自己创建的测试工程。
  - [ ] 正常、失败和异常退出均不调用无条件 `app.quit()`。
  - [ ] 加入明确的 `TEST_PROJECT_MARKER` 身份校验。

### STAB-002：Adobe 可能加载 backup 旧扩展

- **位置**：`packaging/install-internal.command:16-19`、`packaging/uninstall-internal.command:5-18`
- **类别**：安装升级 / 版本可信度
- **证据**：安装器把旧目录改名为 `com.fnnas.seekbridge.mvp.backup.<timestamp>`，但仍留在 Adobe CEP `extensions` 目录。隔离环境连续安装两次后出现两个相同 bundle ID；卸载后 backup manifest 仍存在。当前 Premiere DevTools URL 还观察到从 backup 路径加载扩展。
- **影响**：可能加载旧代码、出现重复菜单或卸载不彻底；测试人员无法确认正在验证哪个版本。
- **修复方向**：备份移出 Adobe 扫描目录；安装前清理或禁用所有同 bundle ID 遗留；启动 UI 显示运行版本和真实扩展路径；卸载覆盖全部同 ID 目录。
- **验收标准**：
  - [ ] 连续安装 3 次，CEP 扫描目录中始终只有一个 manifest 使用该 bundle ID。
  - [ ] 卸载后不存在任何可被 CEP 加载的同 ID manifest。
  - [ ] Premiere DevTools 页面 URL 指向 canonical `com.fnnas.seekbridge.mvp/index.html`。
  - [ ] 面板显示版本为 `0.6.6` 或后续修复版本。

## 6. P1 详细问题

### STAB-003：HEVC 选中预览可能只有声音

- **位置**：`extension/js/main.js:1593-1666`、`extension/js/media-tools.js:726-750`
- **证据**：卡片预览只在媒体元素触发 `error` 时创建代理。若音轨可解码但视频轨未输出帧，整体元素可能继续播放而不触发错误。
- **影响**：用户看到选中框和声音，但缩略图保持黑色或海报不变化。
- **修复方向**：读取 ffprobe codec 后决定是否直放；增加首帧 watchdog，`canplay` 后仍无 `videoWidth`/视频帧则切换 H.264 代理。
- **验收标准**：
  - [ ] H.264、HEVC 8/10-bit、MOV、可变帧率样本均从第 0 秒显示画面并同步声音。
  - [ ] 2 秒内没有视频帧时进入代理流程，而不是无限等待。
  - [ ] 切换卡片会取消旧代理和旧媒体播放。

### STAB-004：SMB 挂起后无法真正取消

- **位置**：`extension/js/library.js:231,297,317`、`extension/js/main.js:816-835`
- **证据**：模拟 `readdir` 永不回调后，即使将 `cancelSignal.cancelled=true`，扫描 Promise 仍保持 pending。当前 15 秒 watchdog 仅提示“仍在后台读取”。
- **影响**：刷新按钮长期禁用，其他素材根无法继续读取，必须重启面板或 Adobe。
- **修复方向**：把网络目录操作隔离到 worker/子进程并设置硬超时；按根独立失败；迟到回调必须忽略。
- **验收标准**：
  - [ ] 单目录超过配置超时后 Promise 必须完成并标记该根离线。
  - [ ] 一个根离线不阻塞其他根。
  - [ ] 用户再次刷新时旧扫描能在限定时间内释放状态。
  - [ ] 测试覆盖永不回调、迟到回调、EIO、ESTALE 和重新挂载。

### STAB-005：安装包未携带或检查 FFmpeg

- **位置**：`extension/js/media-tools.js:571-588`、`scripts/package-internal.command`、`packaging/install-internal.command`
- **证据**：ZIP/DMG 内没有 `ffmpeg`/`ffprobe`；安装器不检查依赖。开发机测试通过依赖 `/opt/homebrew/bin/ffmpeg`。
- **影响**：干净 Mac 上所有依赖 FFmpeg/ffprobe 的元数据、海报、波形、雪碧图、代理、转码和截图能力不可用；浏览器原生支持的媒体仍可能直接播放。
- **修复方向**：合法分发双架构二进制，或安装时做强制依赖检查并提供明确安装路径；面板应显示依赖状态。
- **验收标准**：
  - [ ] Apple Silicon 和 Intel 干净机器完成安装后可读取元数据并生成代理。
  - [ ] 缺少依赖时安装前阻止继续，或面板明确显示降级功能。
  - [ ] 不以静默 catch 隐藏依赖失败。

### STAB-006：FFmpeg 取消可能堵死任务队列

- **位置**：`extension/js/media-tools.js:596-658,936-948`
- **证据**：活动任务收到 `SIGTERM` 后，只有子进程回调才减少 `activeFfmpegCount`。模拟两个不响应退出的任务后，第三个任务无法启动；取消 poster 时还会进入代理和 frame fallback。
- **影响**：两个不退出的任务可以无限期堵住全部预览、转码和截图，直至子进程退出或面板重启。
- **修复方向**：SIGTERM 后设置宽限期并升级 SIGKILL；取消立即让 Promise 进入确定状态；`JOB_CANCELLED` 不得执行 fallback；查看器使用保留优先槽。
- **验收标准**：
  - [ ] 不响应 SIGTERM 的任务在限定时间内被强制回收。
  - [ ] 被取消的 poster 不启动代理或 frame fallback。
  - [ ] 第三个高优先级查看器任务可在取消后及时启动。

### STAB-007：LUT 失败后仍残留 Lumetri 效果

- **位置**：`extension/jsx/host.jsx:682-720`
- **证据**：故障注入中 `addVideoEffect()` 已执行，但 Input LUT 不可写，API 返回 `LUT_UNSUPPORTED` 时 `effectsAdded=1`。多选 2 条只成功 1 条时仍返回 `ok:true`。
- **影响**：失败操作也会改变 Premiere 工程，可能留下空效果或部分应用状态。
- **修复方向**：应用前验证可写能力；定位刚添加的组件而非第一个 Lumetri；全部目标成功才报告成功；失败时撤销或删除新增效果。
- **验收标准**：
  - [ ] 不支持的 Premiere 版本执行后工程效果数量不变。
  - [ ] 多选部分失败时返回部分失败明细，不返回整体成功。
  - [ ] 已有 Lumetri 的素材不会被误写旧效果。

### STAB-008：dragstart 在 drop 前修改工程

- **位置**：`extension/js/main.js:1758-1779`
- **证据**：LUT 在 `dragstart` 立即调用宿主应用；带标签媒体在拖动开始时调用导入。用户取消拖拽也已经产生工程副作用；多选时只处理拖拽起点标签且不等待宿主返回。
- **影响**：违反“只有实际拖入后才增加工程负担”的产品约束，且多选标签可能不一致。
- **修复方向**：拖动阶段只写 DataTransfer；工程写入必须发生在确认的宿主 drop/显式命令后；多选标签按完整列表处理并等待结果。
- **验收标准**：
  - [ ] 拖动后按 Esc，Premiere 项目项和时间线完全不变。
  - [ ] 拖回插件区域不导入、不应用 LUT。
  - [ ] 多选不同标签素材完成 drop 后标签逐项一致。

### STAB-009：Premiere 查重错误使用 `numItems`

- **位置**：`extension/jsx/host.jsx:492-526`、`tests/host-insert-position.test.js:25`
- **证据**：`findItemsMatchingMediaPath()` 返回 Array 或 `0`，但代码只检查 `fastMatches.numItems`。现有测试人为给数组添加 `numItems`，掩盖真实 API 行为。
- **影响**：快速查重失效并同步遍历整个工程；大工程会卡顿，也增加重复导入风险。
- **修复方向**：优先按标准 Array 的 `length` 处理，同时兼容 `0`、空数组和类集合返回值；测试必须使用真实返回形态。
- **参考**：https://ppro-scripting.docsforadobe.dev/item/projectitem/#projectitemfinditemsmatchingmediapath
- **验收标准**：
  - [ ] 普通 Array 返回值使用 `length` 正确命中第一项。
  - [ ] API 返回 `0`、空数组、集合对象时均安全处理。
  - [ ] 测试删除人为 `numItems` 后仍通过。

### STAB-010：跨卷移动失败留下重复文件

- **位置**：`extension/js/asset-ops.js:390-436`
- **证据**：EXDEV fallback 先复制目标，再把源文件移到废纸篓；若废纸篓失败，目标副本未清理。故障注入结果为源文件存在且目标目录同时出现同名副本。
- **影响**：UI 报“移动失败”，实际却新增副本，用户可能误操作或重复占用大量空间。
- **修复方向**：源文件未成功移出时回滚目标副本；对回滚失败返回明确的双路径恢复信息。
- **验收标准**：
  - [ ] Trash 失败后目标副本被清理，源文件保持原位。
  - [ ] 回滚失败时 UI 明确列出源路径和副本路径。
  - [ ] 增加 EXDEV + Trash 失败自动测试。

### STAB-011：批量废纸篓部分成功但 UI 误报

- **位置**：`extension/js/asset-ops.js:488-529`、`extension/js/main.js:2841-2850`
- **证据**：第 1 项成功、第 2 项失败时，错误包含 `partialResults:[第1项]`；UI 忽略它并显示“原文件已保留”，也不刷新素材列表。
- **影响**：用户以为所有文件都还在，但部分文件已经进入废纸篓；直接重试还可能因首项不存在再次失败。
- **修复方向**：返回逐项结果；无论部分成功还是失败都刷新；提示成功数、失败数和失败路径。
- **验收标准**：
  - [ ] 部分成功时 UI 准确显示 `成功 N / 失败 M`。
  - [ ] 已成功项从列表移除，失败项保留。
  - [ ] 重试只处理失败项。

### STAB-012：大素材库全量创建和重绘 DOM

- **位置**：`extension/js/main.js:1244-1347`
- **证据**：620 个素材生成约 7,800 个 DOM 节点；清空搜索约 107ms，切换列表约 56ms，连续状态切换明显超过 16ms 帧预算。扫描上限为 10,000 项。
- **影响**：大型素材库中搜索、排序、调整视图和选择可能冻结 CEP 面板，并加重缩略图任务压力。
- **修复方向**：窗口化/虚拟列表、分页渲染或分帧批量渲染；保留卡片节点并做增量更新；测量真实 CEP 性能。
- **验收标准**：
  - [ ] 10,000 项时首屏交互可在 500ms 内出现。
  - [ ] 搜索和视图切换主线程长任务不超过 50ms，目标低于 16ms。
  - [ ] DOM 节点数量与可视卡片数量同量级，而非与总素材数线性增长。

### STAB-013：工具栏导出入口接错且可重入

- **位置**：`extension/js/main.js:360,2853-2892`
- **证据**：`toolbarExportButton` 直接绑定 `packageCurrentProject()`；在 AE/浏览器仍可见但必然报“仅支持 Premiere”。打包期间只禁用 `packageProjectButton`，导出按钮可重复启动流程。
- **影响**：按钮语义错误；用户可打开多个选择器或并发打包到不同目录。
- **修复方向**：明确导出按钮业务语义；非 Premiere 禁用/隐藏；所有入口共用单一 operation lock。
- **验收标准**：
  - [ ] 导出按钮执行设计定义的动作，不冒充项目打包。
  - [ ] 进行中所有同类入口禁用。
  - [ ] 快速连续点击只产生一个任务。

### STAB-014：缓存 12GB 限制不是硬上限

- **位置**：`extension/js/media-tools.js:521-568`
- **证据**：清理只在启动时调度一次，并跳过 24 小时内生成的所有文件。模拟 14GiB 新缓存时删除数为 0。当前开发机缓存约 662MB、3,638 个文件。
- **影响**：连续预览和代理生成可持续增长，最终可能耗尽系统盘。
- **修复方向**：发布大文件后增量核算；同时考虑硬预算、磁盘剩余空间和正在使用文件；提供清理入口。
- **验收标准**：
  - [ ] 缓存超过硬上限后能回落到目标值。
  - [ ] 不删除正在播放或生成的文件。
  - [ ] 磁盘剩余空间低于阈值时停止新代理并明确提示。

### STAB-024：状态文件损坏后可能覆盖收藏和标签

- **位置**：`extension/js/state-store.js:132-158`、`tests/state-store.test.js:58-69`
- **证据**：`load()` 遇到任何读取或 JSON 解析错误都直接返回默认空状态；下一次 `mutate()` 会把该空状态原子写回主文件，且没有可恢复的 `.bak`。故障注入中截断一个含收藏信息的 `state.json` 后，载入结果为 `assetMeta={}`；再执行一次写入，磁盘上的旧状态被空状态覆盖。现有测试只断言损坏后返回空状态，没有验证用户数据保全。
- **影响**：一次写入中断、磁盘错误或手工损坏就可能永久清空收藏、色彩标签、插件文件夹和素材位置，违反这些信息长期保留的产品要求。
- **修复方向**：维护经过验证的 last-known-good 备份；主文件解析失败时只读恢复备份并隔离损坏文件；主备份都损坏时明确提示，在用户确认前禁止用默认空状态覆盖原文件。
- **验收标准**：
  - [ ] 主状态文件被截断或写入非法 JSON 后，可从备份恢复收藏、标签、插件文件夹和素材位置。
  - [ ] 损坏的主文件被隔离保存，后续普通操作不会把空状态覆盖到主备份。
  - [ ] 主文件和备份都损坏时显示可操作错误，并保留两个原始文件供恢复。
  - [ ] 增加主文件损坏、备份损坏、双文件损坏和恢复后再次写入测试。

### STAB-025：批量元数据操作逐项同步重写完整状态

- **位置**：`extension/js/main.js:237-249,1928-1960`、`extension/js/state-store.js:132-159`
- **证据**：批量收藏、置顶、粘贴标签和清除标签都会为每个素材调用一次 `updateLocalMeta()`；每次调用又同步读取、解析、规范化并重写包含 `libraryCache` 的完整状态文件。使用约 839KB、1,937 条缓存素材的真实状态副本，300 项批量写入耗时约 1.31 秒；按当前实现线性外推，1,133 项约需数秒。
- **影响**：批量选择大量素材后操作会阻塞 CEP UI 线程，表现为插件冻结、点击无响应；SMB 或慢磁盘环境会进一步放大延迟。
- **修复方向**：新增一次事务内更新多个素材的批量 API；将与渲染无关的状态读写移出热路径；状态写入使用合并、防抖和可观测耗时预算。
- **验收标准**：
  - [ ] 1,000 项收藏、置顶、粘贴标签和清除标签均只执行一次状态事务。
  - [ ] 1,000 项操作期间界面保持可响应，并显示必要的进行中反馈。
  - [ ] 批量写入失败时不出现部分内存状态、部分磁盘状态。
  - [ ] 性能测试记录不同状态文件大小下的总耗时和主线程长任务。

## 7. P2 详细问题

### STAB-015：打包取消后残留已复制文件

- **位置**：`extension/js/project-packager.js:507-630`
- **证据**：完成第 1 个文件后取消，第 1 个文件仍留在目标目录且没有最终 manifest。
- **影响**：目标路径中会留下外观近似完整、实际不可验证的不完整交付包，容易被同事误用。
- **修复方向**：使用临时 staging 目录，完整成功后原子发布；取消或 manifest 失败时清理 staging。
- **验收标准**：取消、宿主关闭和写清单失败均不留下看似完整的包。

### STAB-016：300/320px 关键按钮越界

- **位置**：`extension/CSXS/manifest.xml:46-49`、`extension/css/ui-4.3.css:299-305`
- **证据**：manifest 支持最小宽度 300px；实测 300px 时“更多”和“勾选”越出右侧，320px 时勾选仍完全不可见。
- **影响**：用户把面板停靠到窄栏时无法访问关键操作，且工具栏出现明显错位和裁切。
- **修复方向**：分类行在窄宽度拆成两行或压缩分类间距，关键操作固定在可视区。
- **验收标准**：300px 下所有主要操作无需横向滚动即可访问。

### STAB-017：隐藏控件仍进入键盘焦点顺序

- **位置**：`extension/css/panel.css:183-184`、`extension/css/ui-4.3.css:82-84`
- **证据**：空搜索时透明的清除按钮仍可 Tab；缩放浮层关闭时透明 range 仍可 Tab，并获得一个不可见的 180x34 焦点区域。
- **影响**：键盘用户会进入不可见控件，焦点位置难以判断。
- **修复方向**：隐藏时设置 `tabindex=-1`、`disabled` 或 `visibility:hidden`；打开时恢复。
- **验收标准**：完整 Tab 顺序只经过当前可见和可用控件。

### STAB-018：Premiere 大工程同步遍历无超时

- **位置**：`extension/jsx/host.jsx:880-932`、`extension/js/main.js:2853-2880`
- **证据**：ExtendScript 同步遍历全部序列、视频轨、音频轨和 clip；前端 `evalScript` 没有超时或取消。
- **影响**：大型工程执行项目打包清单时可能长时间冻结 Premiere，按钮也会保持禁用。
- **修复方向**：缓存、分批处理、进度心跳和前端超时；至少对超大项目提前告知并允许取消。
- **验收标准**：大型测试工程有持续进度反馈，超时后前端能恢复可操作状态。

### STAB-019：插入硬编码 V1/A1

- **位置**：`extension/jsx/host.jsx:568-608`
- **证据**：`videoTrackIndex=0`、`audioTrackIndex=0`，没有检查锁定、目标轨或媒体类型。
- **参考**：https://ppro-scripting.docsforadobe.dev/sequence/sequence/#sequenceinsertclip
- **影响**：复杂时间线可能插入失败、落错轨或与用户当前目标轨不一致。
- **修复方向**：检测目标轨、锁定状态和轨道类型；失败时明确说明选中的目标轨问题。
- **验收标准**：覆盖锁定 V1、无音频轨、纯音频、纯视频、多目标轨等工程。

### STAB-020：部分音频格式没有代理回退

- **位置**：`extension/js/main.js:1565-1575,2171-2177`
- **证据**：音频悬停和播放器都直接加载源文件，播放拒绝和解码失败被静默吞掉。
- **影响**：CEP 不能直接解码的音频会表现为无声音、无错误提示，用户无法区分格式不支持和播放失败。
- **修复方向**：监听媒体错误并调用 `audioProxyFor()`；区分浏览器自动播放拒绝和编码不支持。
- **验收标准**：WAV、AIFF、AAC、M4A、MP3、FLAC 等支持列表样本逐一验证；直放失败后自动生成代理并在限定时间内出声；切换素材后旧播放立即终止。

### STAB-021：缓存失效和临时目录清理不完整

- **位置**：`extension/js/media-tools.js:888-915,950-989`
- **证据**：缓存键只使用路径、大小和 mtime；SMB 原位替换且保持大小/时间时可能继续使用旧缓存。设计文件成功走 `pdftoppm` 或异常分支时可能残留临时目录。
- **影响**：用户可能持续看到已被替换素材的旧画面，长期使用还会积累无法自动清除的临时文件。
- **修复方向**：加入 inode/ctime 或轻量内容指纹；所有临时目录通过统一 finally 清理；增加“重新生成预览”。
- **验收标准**：同路径内容替换后预览更新；成功、失败、取消均无临时目录残留。

### STAB-022：SMB 重命名使用同步文件系统 API

- **位置**：`extension/js/file-ops.js:29-75`
- **证据**：`existsSync`、`lstatSync`、`realpathSync`、`readdirSync`、`renameSync` 均运行在 CEP UI 线程且无超时。
- **影响**：共享盘掉线或超大目录中重命名可能冻结整个面板。
- **修复方向**：统一迁移到异步 `asset-ops` 路径并使用网络超时/取消机制。
- **验收标准**：断开 SMB 后执行重命名，面板仍可操作且在限定时间内给出错误。

## 9. 系统性问题

1. **测试偏向源码存在性，而非真实行为**：`tests/ui-contract.test.js` 多数使用正则确认代码片段，不能证明媒体真的解出首帧、控件可点击或宿主操作可回滚；状态损坏测试也只验证回到空状态，没有验证数据恢复。
2. **异步操作缺少统一生命周期**：扫描、FFmpeg、宿主 `evalScript`、打包各自维护取消状态，没有共享的 operation controller、超时和最终清理规则。
3. **跨边界操作缺少事务语义**：文件移动、批量删除、LUT 应用和打包都允许部分完成，但 UI 多以整体成功/失败呈现。
4. **安装版本不可观测**：面板没有显示真实加载路径，backup 目录又处于 CEP 扫描范围，导致测试基线不可靠。
5. **大数据量没有渲染和写入预算**：扫描允许 10,000 项，但渲染、排序和状态写入仍按全量同步模型实现；批量元数据更新还会逐项重写完整状态。

## 10. 正向结果

- 源文件路径、realpath 和符号链接边界校验较严格。
- 外部复制和副本创建使用排他写入，默认不覆盖现有文件。
- 删除采用 macOS Foundation Trash，不包含永久删除源素材路径。
- 项目打包只处理 Premiere 报告且位于授权根内的实际使用素材，不扫描无关目录。
- 当前 UI 文本对比度约为 6.0:1 至 14.6:1，主要文字满足 WCAG AA。
- 自动测试与 JavaScript/Zsh/XML 语法检查通过；自动脚本覆盖的 package、manifest 和 host 版本字段一致。
- 故障注入没有修改用户真实素材或 Premiere/AE 工程。

## 12. 单项修复工作流

每修复一个编号，按下面顺序执行：

1. 在本报告总表把状态改为“修复中”。
2. 先添加能稳定复现该问题的自动测试或故障注入测试。
3. 实现最小范围修复，避免捎带 UI 重构。
4. 运行 `npm test`、`npm run check` 和对应专项测试。
5. 在 Premiere/AE/干净安装环境执行需要的宿主复测。
6. 填写修复提交和复测结果，把状态改为“已通过”或“部分通过”。
7. 所有 P0/P1 完成后重新运行完整稳定性审查。

建议严格按第 11 节的五个批次推进；每完成一批，再执行对应专项复测，最后进行完整回归。
